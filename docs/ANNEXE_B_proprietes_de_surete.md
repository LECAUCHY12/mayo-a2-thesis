# Annexe B — Propriétés sur lesquelles repose A2 SAFE

Chaque propriété est étiquetée selon sa **source de justification** : **[C]** découle du code et de ses invariants (relecture du source, assertions de compilation) ; **[E]** vérifiée expérimentalement ; **[H]** hypothèse sur la machine ou le compilateur. Une propriété [E] seule n'est pas une démonstration. Paramètres : MAYO-1 : m = 80, b = m/2 = 40 octets par m-vec, L = 5 limbes de 8 octets, K = 10, V = 80 ; MAYO-5 : m = 142, b = 71, L = 9, K = 12, V = 142. NENT = V(V+1)/2 entrées de P1 : 3 240 (MAYO-1), 10 153 (MAYO-5). Notation : n_y = ⌊m/64⌋ registres ymm pleins (1 et 2), TOFF = 32·n_y (32 et 64), TLIMB = 4·n_y (limbe de queue : 4 et 8).

## B.1 Bornes de lecture de P1 (code : `MTX_STEP`, `mtx_tail_prep`, `PINV`)
L'entrée e (0 ≤ e < NENT) occupe les octets [e·b, (e+1)·b) de P1 (adresse calculée en octets : `PINV`).
- **B.1a [C]** Les n_y chargements ymm lisent [e·b + 32g, e·b + 32g + 32), g < n_y. Comme 32·n_y ≤ b (32 ≤ 40 ; 64 ≤ 71), ils restent dans l'entrée.
- **B.1b [C]** MAYO-1 : la queue lit [e·b + 32, e·b + 40) : exactement la fin de l'entrée (TOFF + 8 = b, branche non SAFE de `MTX_OVERREAD` = 0).
- **B.1c [C]** MAYO-5, variante SAFE : la queue lit [e·b + 63, e·b + 71) (chargement de 8 octets à TOFF − 1) puis décale le registre de 8 bits vers les poids faibles : l'octet 63 est éliminé, les octets 64..70 sont placés aux positions 0..6, la position 7 reçoit 0. Toute lecture reste dans [e·b, (e+1)·b).
- **B.1d [C]** (variante par défaut, non retenue) MAYO-5 lit [e·b + 64, e·b + 72) : un octet au-delà de l'entrée. Pour e < NENT − 1 c'est le premier octet de l'entrée suivante ; pour la dernière entrée, c'est l'octet NENT·b = 720 863 du tampon `sk->p`/`pk->p`, alloué (zone réservée à P1 : 8·P1_LIMBS_MAX = 731 016 octets). Les `_Static_assert` du code imposent `NENT·b + OVERREAD ≤ 8·P1_LIMBS_MAX` et `OVERREAD ≤ 1`.
- **B.1e [E]** Test garde-page (fin de P1 collée à une page interdite, marge 0) : officiel et A2 par défaut déclenchent SIGSEGV en MAYO-5, A2 SAFE non, MAYO-1 aucun des trois. Ce test est un contrôle de B.1c, il ne la démontre pas.
- **Remarque de contexte.** Le noyau officiel de MAYO-5 lit lui aussi 1 octet au-delà (dernier ymm à `M_VEC_LIMBS_MAX − 4` limbes = octets 40..71), et celui de MAYO-3 en lit 2 (second ymm sur [24, 56) pour b = 54). Le backend GFNI lit en pleine largeur dans une marge `MAYO_MVEC_SLACK`. A2 SAFE ne dépend d'aucune marge.

## B.2 Bornes d'écriture (accumulateurs)
Pour chaque ligne r < V, l'accumulateur est `ar = acc + r·K·L` (en limbes) ; le vecteur k occupe les limbes [k·L, (k+1)·L).
- **B.2a [C]** Les stockages ymm écrivent les limbes [k·L + 4g, k·L + 4g + 4), g < n_y : jamais au-delà du limbe 4·n_y − 1 ≤ L − 1 (3 ≤ 4 ; 7 ≤ 8).
- **B.2b [C]** La queue lit-modifie-écrit un seul limbe de 64 bits, le limbe TLIMB = 4·n_y = L − 1 (4 et 8), pour k < K (et k+1 < K pour le second, garde explicite).
- **B.2c [C]** Donc toutes les écritures sont dans les V·K·L limbes de `acc`. L'officiel écrit un ymm à `L − 4` (chevauchant) : même étendue. **[E]** Un « canari » placé après `acc` n'est pas modifié (test unitaire : `limbes complets + canari`, 0 écart).
- **B.2d [C]** `P1` est passé en `const uint64_t *` ; **[E]** la copie de l'entrée n'est pas modifiée (`entrée modifiée : 0`).

## B.3 Invariant des deux voies des tables de multiplication
A2 lit la voie basse (128 bits) de chaque table pour la queue et suppose qu'elle égale la voie haute.
- **Lemme S3 [C].** Pour tout i, `V_multabs[i]` a ses deux voies de 128 bits égales. *Justification* : (i) chacune des quatre lignes de 32 octets de `__gf16_mulbase` répète deux fois la même suite de 16 octets (constantes lues dans le source : `arithmetic_common.h`, lignes 12–17) ; (ii) `tbl32_gf16_multab2(b)` est un OU exclusif de ET entre ces lignes et des masques obtenus par `_mm256_set1_epi16(b & 0xf)` décalé et comparé, opérations qui agissent par élément de 16 bits donc par voie de 128 bits, et dont les masques sont identiques dans les deux voies ; (iii) `mayo_V_multabs` combine deux telles tables par `^` et par `_mm256_slli_epi16(·, 4)`, également lane-wise. Par induction, l'égalité des voies est conservée.
- **B.3b [E]** 272 tables vérifiées avec le mode `MAYO_TAIL_XMM_CHECK` (abort sinon) sur les tables réellement passées aux noyaux.
- **Précondition.** Si les tables étaient construites autrement (autre routine, autre backend), l'invariant devrait être revérifié : c'est une **précondition d'A2**.

## B.4 Influence des quartets de bourrage
Seul MAYO-5 a des quartets de bourrage (m = 142, L·16 = 144 : positions 142 et 143). MAYO-1 n'en a pas (80 = 5·16).
- **B.4a [C] Indépendance positionnelle.** Dans les noyaux (officiel et A2), la sortie à la position j ne dépend que des entrées à la position j de chaque m-vec : une recherche `vpshufb` lit un index et une table, jamais un autre index ; les décalages `_mm256_srli_epi16/slli_epi16` mélangent deux octets voisins dans un élément de 16 bits mais chaque résultat est suivi d'un ET avec `0x0f` (ou provient d'un registre déjà masqué), ce qui élimine tout quartet venu d'un octet voisin ; `mtx_tail_prep` fait de même (ET par `0x0f` après `unpacklo`).
- **B.4b [C]** Les deux différences entre officiel et A2 dans les positions de bourrage sont : officiel : produits de l'octet 71 (premier octet de l'entrée suivante) ; A2 SAFE : 0 (la position 7 de la queue est nulle, et la table envoie 0 sur 0). Elles n'existent qu'aux positions 142 et 143.
- **B.4c [C]** Les noyaux A2 alimentent `Pv`, puis `Vt_times_Pv` produit `VP1V`, consommé par `compute_rhs`, premier consommateur qui mélange des positions ; il annule les quartets de bourrage avant usage : `src/mayo.c`, lignes 50–60 (`vPv[...] &= mask` avec `mask = (1 << ((m % 16)·4)) − 1`, commentaire du code : « zero out tails of m_vecs if neccesary »). Entre les noyaux et `compute_rhs`, les opérations (`Vt_times_Pv`, additions) sont positionnelles (B.4a). (Le masquage analogue de `VtL` aux lignes 148–157 concerne `compute_A` et la sortie de `Vt_times_L`, que A2 ne modifie pas.)
- **B.4d [E]** Tests unitaires (20 000 cas par taille, 8 familles d'entrées) : 0 écart sur les M_MAX/2 octets utiles de chaque m-vec, ainsi que sur les limbes complets après masquage de l'octet de bourrage ; et sur 30 010 signatures appariées de MAYO-5 (et 15 005 pour MAYO-1 et MAYO-2), 0 signature différente. Modifier les octets situés après la fin de P1 (A5…) ne change que le bourrage.
- **Limite.** B.4c suppose que `Pv` n'est consommé que par les chemins énumérés. Cette énumération a été faite par recherche dans le source du backend AVX2 ; une modification future qui lirait le bourrage de `Pv` devrait être réexaminée.

## B.5 Propriétés de temps constant (à distinguer de la correction)
- **B.5a [C]** Dans les noyaux, les bornes de boucle (V, K) et les adresses des chargements (e·b) dépendent de paramètres publics. Les valeurs secrètes (tables `V_multabs`, dérivées du vinaigre) ne sont que des opérandes de **données** de `vpshufb`, jamais des adresses ni des conditions de branchement. L'officiel a la même structure.
- **B.5b [C → à vérifier sur le binaire]** A2 introduit, dans le réassemblage de la queue, deux `vmovq` d'un registre vectoriel vers un registre général (`ar[...] ^= (uint64_t)_mm_cvtsi128_si64(...)`) : des données dérivées du secret transitent par un registre général, uniquement comme opérande d'un XOR vers la mémoire. L'officiel n'a pas ces transferts. L'inspection de l'assembleur de la machine physique (script `inspect_asm.py`) n'y trouve **aucun usage non conforme** (adresse, branche, drapeau) : résultat observé pour une version de GCC, pas une garantie pour toute compilation.
- **B.5c [E, indicateur]** Valgrind en mode CT (données secrètes marquées indéfinies) sur la VM ; non exécuté sur la machine physique (Valgrind absent). Il détecte les branches et adresses dépendant de données marquées dans les exécutions testées : c'est un indicateur.
- **B.5d [H]** Les instructions `vpshufb`, `vpxor`, `vpand`, décalages, chargements et stockages ont un temps indépendant des données sur les microarchitectures visées. C'est une hypothèse sur la machine (documentation de fabricant, non vérifiée ici).
- **Absence de preuve formelle.** Aucun outil de vérification formelle de temps constant n'a été appliqué. La réussite des KAT et l'absence de différence fonctionnelle (B.4d) **ne démontrent pas** le temps constant.

## B.6 Représentation et préconditions, en résumé
(1) P1 est dans la disposition empaquetée du flux de clé (2 quartets par octet, quartet bas d'abord), sans bourrage entre entrées, à l'adresse `P1 + e·b` ; (2) les m-vec d'accumulateur ont L limbes de 64 bits avec bourrage de quartets en fin de dernier limbe seulement ; (3) `V_multabs` est construit par `mayo_V_multabs` (B.3) ; (4) les paramètres sont M_MAX ∈ {80, 142} (le code est compilé hors de ces valeurs sans les noyaux A2 : condition `MAYO_TAIL_XMM_ACTIVE`) ; (5) compilation sans `ENABLE_PARAMS_DYNAMIC`.
